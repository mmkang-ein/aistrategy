# 안전 임계 AI 시스템을 위한 계층적 자동화 테스팅 오케스트레이터: 인과 오류 전파 그래프와 정보이론적 교차 강화 기반 통합 테스팅 프레임워크

---

## Abstract

안전 임계 컴퓨터 비전 AI 시스템의 신뢰성 확보를 위해, 본 연구는 정보이론적 교차 강화 선택 함수와 계층 간 인과 오류 전파 그래프를 통합한 자동화 테스팅 오케스트레이터(HATO)를 제안한다. 기능 테스트 경계 케이스의 예측 엔트로피와 적대적 시드 다양성(KL 발산)을 결합한 선택 함수 S(x)를 통해 테스트 효율을 극대화하고, PC/GES 알고리즘 기반 인과 DAG로 계층 간 버그 전파를 모델링하여 안전 임계 버그 탐지율(FNRA)을 통계적으로 유의미하게 향상시킴을 자율주행 및 산업 결함 검출 도메인에서 검증한다.

**Keywords:** AI 테스팅, 안전 임계 시스템, 적대적 강건성, 인과 추론, 벤치마크 평가, 딥러닝 검증

## 1. Introduction

### 1.1 연구 배경 및 동기

딥러닝 기반 컴퓨터 비전 시스템은 자율주행, 의료 영상 진단, 산업 품질 검사 등 안전 임계(safety-critical) 도메인에 급속히 배포되고 있다. 그러나 이러한 시스템의 신뢰성을 보장하기 위한 테스팅 방법론은 여전히 심각한 한계를 내포하고 있다. 2025-2026년 현재, 표준 벤치마크의 포화(saturation) 문제와 실험실-배포 환경 간 성능 격차(lab-to-deployment gap)가 AI 시스템 검증의 핵심 과제로 부상하고 있다 [LeCun et al., 2015; Goodfellow et al., 2014].

기존 테스팅 패러다임은 크게 두 가지 방향으로 분리되어 발전해 왔다. **기능 테스팅(functional testing)** 은 모델 기반 테스트 생성(MBTG)을 통해 시스템 명세 준수 여부를 검증하지만, 실제 배포 환경에서 발생하는 분포 이동(distribution shift)과 적대적 공격에 취약하다. 반면 **적대적 테스팅(adversarial testing)** 은 FGSM, PGD 등의 공격 기법으로 모델의 강건성을 평가하지만, 기능적 안전 명세와의 연계가 부족하여 탐지된 취약점의 실제 안전 영향을 정량화하기 어렵다.

더욱 근본적인 문제는 **계층 간 오류 전파(cross-layer error propagation)** 가 기존 테스팅 프레임워크에서 체계적으로 다루어지지 않는다는 점이다. 딥러닝 시스템에서 하위 레이어의 미세한 이상은 중간 모듈의 인터페이스 계약 위반을 거쳐 최종 안전 명세 위반으로 전파될 수 있으나, 이 인과적 연쇄를 모델링하는 연구는 극히 제한적이다.

또한 벤치마크 데이터셋의 편향 문제는 딥러닝 모델의 일반화 능력을 심각하게 제한한다. 데이터 누수(data leakage), 단일 편향 중심의 벤치마크 설계, 교차 데이터셋 일반화의 어려움 등이 모델 성능 평가의 신뢰성을 저해하며, 이는 안전 임계 시스템에서 치명적 결과를 초래할 수 있다.

본 연구는 이러한 한계를 극복하기 위해 **계층적 자동화 테스팅 오케스트레이터(Hierarchical Automated Testing Orchestrator, HATO)** 를 제안한다. HATO는 기능 테스팅과 적대적 테스팅을 정보이론적으로 연결하는 교차 강화 메커니즘과, 계층 간 오류 전파를 인과 그래프로 모델링하는 방식을 통합하여 안전 임계 버그 탐지율을 획기적으로 향상시킨다.

### 1.2 핵심 기여 (Contributions)

본 연구의 주요 기여는 다음 세 가지로 요약된다:

**기여 1: 정보이론적 교차 강화 선택 함수의 형식적 정의**
기존 coverage-guided fuzzing이 코드 커버리지 증가만을 목적으로 삼는 것과 달리, 기능 테스트 경계 케이스의 예측 엔트로피 H(f(x))와 시드 다양성(KL 발산 D_KL)을 정규화 후 결합한 선택 함수 S(x) = λ·H̃(f(x)) + (1-λ)·D̃_KL을 제안한다. 이를 통해 경계 케이스에서 적대적 시드로의 변환을 확률론적으로 정량화하고, 다양성-안전성 트레이드오프를 측정 가능한 형태로 제시한다.

**기여 2: 계층 간 인과 오류 전파 DAG 학습 메커니즘**
하위 계층(레이어 출력 이상) → 중간 계층(모듈 인터페이스 위반) → 상위 계층(안전 명세 위반) 간 인과 관계를 PC/GES 알고리즘으로 학습한 방향성 비순환 그래프(DAG)로 모델링한다. 이 인과 구조를 활용하여 하위 계층 버그의 상위 계층 전파 확률을 추론하고 테스트 우선순위를 결정하는 메커니즘은 기존 ML 테스팅 문헌에 없는 신규 기여이다.

**기여 3: FNRA 메트릭의 삼중 검증 체계**
기존 연구에서 ground truth 확보 방법이 불명확했던 한계를 (i) 전문가 레이블링(Cohen's κ ≥ 0.8), (ii) CVE/버그 리포트 데이터베이스 매핑, (iii) 변이 테스팅(mutation testing)의 삼중 검증 체계로 해결하여 FNRA(False Negative Rate under Attack) 메트릭의 재현 가능성을 보장한다.

## 2. Related Work

### 2.1 딥러닝 모델 테스팅 및 평가 방법론

딥러닝 모델 테스팅 분야는 크게 화이트박스 접근법과 블랙박스 접근법으로 구분된다. **DeepXplore** [Pei et al., 2017]는 뉴런 커버리지(neuron coverage)를 최대화하는 테스트 케이스를 생성하는 화이트박스 접근법의 선구적 연구로, 차등 테스팅(differential testing)을 통해 DNN의 오동작을 탐지한다. 그러나 뉴런 커버리지가 실제 버그 탐지 능력과 강한 상관관계를 가지는지에 대한 의문이 제기되었다 [Harel-Canada et al., 2020].

**RobOT** [Dong et al., 2022]는 강건성 테스팅을 위한 최적화 기반 프레임워크로, 테스트 케이스의 다양성과 적대적 강건성을 동시에 고려한다. 그러나 기능 테스팅과 적대적 테스팅 간의 체계적 연계 메커니즘이 부재하다는 한계가 있다.

모델 기반 테스트 생성(MBTG) 분야에서는 상태 기계 모델을 활용하여 시스템 동작을 추상화하고 테스트 케이스를 자동 생성하는 연구들이 활발히 진행되었다 [Utting & Legeard, 2010]. 최근에는 결정 테이블 기반 3D 모델과 AI V&V(Verification and Validation) 프레임워크를 결합한 접근법이 제안되었다 [ISO/IEC 29119, 2022].

### 2.2 적대적 강건성 평가

적대적 공격과 방어 메커니즘에 관한 연구는 FGSM [Goodfellow et al., 2014], PGD [Madry et al., 2018], C&W [Carlini & Wagner, 2017] 등의 공격 기법과 이에 대응하는 방어 전략을 중심으로 발전해 왔다. 최근에는 L0/L∞ 규범 기반 평가에서 벗어나 NCCR(Normalized Certified Corruption Robustness) 메트릭, 자연적 섭동(natural perturbation), 스파이킹 신경망(SNN) 특화 평가 방법론으로 연구 범위가 확장되고 있다.

**AutoAttack** [Croce & Hein, 2020]은 파라미터 없는 앙상블 공격 프레임워크로, 기존 강건성 평가의 과대 추정 문제를 해결하였다. 그러나 이러한 접근법들은 여전히 개별 모델 수준의 평가에 집중하며, 시스템 수준의 안전 명세와의 연계가 부족하다.

### 2.3 벤치마크 데이터셋 편향과 일반화

벤치마크 데이터셋의 편향 문제는 딥러닝 커뮤니티에서 지속적으로 제기되어 온 핵심 과제이다. **ImageNet** [Deng et al., 2009]의 레이블 오류와 분포 편향 [Northcutt et al., 2021], **CIFAR** 데이터셋의 교차 데이터셋 일반화 실패 사례들은 벤치마크 신뢰성에 대한 근본적 의문을 제기한다.

최근 연구들은 다중 벤치마크 앙상블 평가, 분포 외(out-of-distribution) 테스팅, 데이터셋 카트그래피(dataset cartography) 등을 통해 일반화 가능성을 향상시키려는 시도를 보여준다 [Swayamdipta et al., 2020]. **MVTec AD** [Bergmann et al., 2019]는 산업 결함 검출을 위한 표준 벤치마크로, 15개 카테고리에 걸친 다양한 결함 유형을 포함하여 실제 산업 환경의 복잡성을 반영한다.

### 2.4 자동화 테스팅 및 MLOps

머신러닝 모델의 자동화된 테스팅은 성능 평가와 신뢰성 확보에 필수적이며, **AutoML** 플랫폼과 **Deepchecks** 같은 도구들이 분류·회귀 작업별 다양한 메트릭 자동화를 지원한다. **MLflow** [Zaharia et al., 2018]와 **Weights & Biases** [Biewald, 2020]는 실험 추적과 모델 버전 관리를 위한 표준 MLOps 플랫폼으로 자리잡았다.

Coverage-guided fuzzing 분야에서는 **AFL** [Zalewski, 2014]과 **LibFuzzer** [Serebryany, 2016]가 소프트웨어 테스팅에서 뛰어난 성과를 보였으나, 딥러닝 시스템에 직접 적용하기 위해서는 커버리지 메트릭의 재정의가 필요하다 [Odena & Goodfellow, 2019].

### 2.5 본 연구와의 차별점

기존 연구들과 비교하여 본 연구는 다음과 같은 명확한 차별점을 가진다:

| 특성 | DeepXplore | RobOT | 기존 MBTG | **HATO (본 연구)** |
|------|-----------|-------|-----------|------------------|
| 기능-적대적 연계 | ✗ | 부분적 | ✗ | **정보이론적 형식화** |
| 계층 간 인과 모델링 | ✗ | ✗ | ✗ | **인과 DAG** |
| Ground Truth 검증 | 불명확 | 불명확 | 불명확 | **삼중 검증** |
| 안전 명세 연계 | 부분적 | ✗ | ✓ | **통합** |
| MLOps 통합 | ✗ | ✗ | ✗ | **REST API** |

## 3. Methodology

### 3.1 시스템 아키텍처 개요

HATO는 6개의 상호 연결된 모듈로 구성된다 (Figure 1 참조):

```
┌─────────────────────────────────────────────────────────────┐
│                    HATO 오케스트레이터                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │ 상태기계  │→│ 교차강화  │→│ 인과DAG  │→│  FNRA    │   │
│  │  모델    │  │ 선택함수  │  │  학습    │  │  평가    │   │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘   │
│         ↑              ↓              ↓              ↓       │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────────┐  │
│  │ 실행추적  │  │ 적대적   │  │  MLOps 통합 (MLflow/W&B) │  │
│  │  수집    │  │  퍼징    │  │                          │  │
│  └──────────┘  └──────────┘  └──────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

**Figure 1.** HATO 시스템 아키텍처. 상태 기계 모델, 교차 강화 선택 함수, 인과 DAG 학습, FNRA 평가 모듈이 유기적으로 연결된다.

### 3.2 1단계: 실행 추적 기반 상태 기계 모델 구성

#### 3.2.1 추상 상태 도출

시스템 실행 로그에서 추상 상태를 자동으로 도출하기 위해 k-means 클러스터링을 적용한다. 상태 수 k는 사전에 k ≤ 50으로 상한선을 고정하여 계산 복잡도를 제어한다.

**알고리즘 1: 실행 추적 기반 상태 도출**

```
입력: 실행 로그 집합 L = {l₁, l₂, ..., lₙ}
출력: 추상 상태 집합 S = {s₁, s₂, ..., sₖ}

1. 각 로그 lᵢ에서 특징 벡터 φ(lᵢ) ∈ ℝᵈ 추출
   (활성화 패턴, 레이어 출력 통계, 인터페이스 호출 시퀀스)
2. k-means 클러스터링: argmin_S Σᵢ min_j ||φ(lᵢ) - μⱼ||²
   (k는 실루엣 계수 최대화로 자동 선택, k ≤ 50 제약)
3. 전이 확률 MLE 추정: P(sⱼ|sᵢ) = count(sᵢ→sⱼ) / count(sᵢ)
4. 전문가 검토: 상태 레이블링 단계만 개입 (목표: ≤ 20인시/도메인)
```

#### 3.2.2 테스트 케이스 자동 생성

상태 기계 모델로부터 경계값 분석(BVA)과 동등 분할(EP)을 자동 적용하여 기능 테스트 케이스를 생성한다:

- **경계값 분석**: 각 상태 전이의 입력 도메인 경계에서 테스트 케이스 생성
- **동등 분할**: 동일한 동작을 유발하는 입력 클래스를 분할하여 대표 케이스 선택
- **경로 커버리지**: 상태 전이 그래프의 모든 에지를 최소 1회 순회하는 테스트 시퀀스 생성

### 3.3 2단계: 정보이론적 교차 강화 선택 함수

#### 3.3.1 선택 함수의 형식적 정의

기존 coverage-guided fuzzing과의 핵심 차별점은 선택 함수 S(x)의 정보이론적 정형화에 있다. 본 연구는 두 구성 요소를 [0,1] 범위로 정규화한 후 결합하여 단위 일관성을 보장한다.

**정규화된 예측 엔트로피:**

$$\tilde{H}(f(x)) = \frac{H(f(x))}{H_{max}} = \frac{-\sum_{c=1}^{C} p_c \log p_c}{\log C}$$

여기서 C는 클래스 수, p_c는 클래스 c에 대한 예측 확률이다. H̃(f(x)) ∈ [0,1]이며, 1에 가까울수록 모델이 높은 불확실성을 보이는 경계 케이스임을 의미한다.

**정규화된 KL 발산:**

$$\tilde{D}_{KL}(p_{new}||p_{existing}) = 1 - \exp\left(-D_{KL}(p_{new}||p_{existing})\right)$$

이 변환은 KL 발산의 [0, ∞) 범위를 [0, 1)로 매핑하며, 기존 시드 집합과의 다양성을 측정한다.

**통합 선택 함수:**

$$S(x) = \lambda \cdot \tilde{H}(f(x)) + (1-\lambda) \cdot \tilde{D}_{KL}(p_{new}||p_{existing}), \quad \lambda \in [0,1]$$

#### 3.3.2 λ 최적화 절차

λ 파라미터는 내부 검증 세트(hold-out, 전체 데이터의 20%)에서 그리드 서치로 최적화하며, 테스트 세트와 엄격히 분리하여 과적합을 방지한다:

```
λ* = argmax_{λ∈{0.0, 0.1, ..., 1.0}} FNRA_reduction(λ; D_validation)
```

최적 λ*는 도메인별로 독립적으로 결정되며, 자율주행 도메인과 산업 결함 검출 도메인에서 각각 별도로 보고한다.

#### 3.3.3 교차 강화 메커니즘

교차 강화는 다음 절차로 수행된다:

1. **기능 테스팅 실행**: MBTG로 생성된 테스트 케이스 T_func 실행
2. **경계 케이스 식별**: S(x) > θ_boundary인 케이스를 경계 케이스 집합 B로 분류
3. **적대적 시드 선택**: B에서 S(x) 기준 상위 k%를 적대적 퍼징의 초기 시드로 활용
4. **적대적 테스팅 실행**: PGD 기반 공격으로 선택된 시드 주변 탐색
5. **피드백 루프**: 새로 발견된 취약점을 기능 테스트 케이스 갱신에 반영

### 3.4 3단계: 계층 간 인과 오류 전파 그래프

#### 3.4.1 계층적 오류 분류 체계

시스템 오류를 세 계층으로 분류한다:

- **L1 (하위 계층)**: 개별 레이어 출력 이상 (활성화 값 이상, 그래디언트 폭발/소실)
- **L2 (중간 계층)**: 모듈 인터페이스 계약 위반 (출력 범위 위반, 타입 불일치)
- **L3 (상위 계층)**: 최종 안전 명세 위반 (충돌 회피 실패, 결함 미탐지)

#### 3.4.2 인과 DAG 학습

계층 간 인과 관계를 PC(Peter-Clark) 알고리즘 또는 GES(Greedy Equivalence Search) 알고리즘으로 학습한다:

**PC 알고리즘 적용:**

```
입력: 오류 관측 데이터 행렬 X ∈ ℝ^{n×(|L1|+|L2|+|L3|)}
출력: 인과 DAG G = (V, E)

1. 완전 무방향 그래프로 초기화
2. 조건부 독립성 검정으로 에지 제거
   (Fisher's Z 검정, α = 0.01)
3. v-구조(v-structure) 방향 결정
4. 방향 전파 규칙 적용 (Meek rules)
5. 계층 제약 적용: L1 → L2 → L3 방향성 강제
```

#### 3.4.3 인과 전파 확률 추론

학습된 DAG를 활용하여 하위 계층 버그의 상위 계층 전파 확률을 추론한다:

$$P(L3_{violation} | L1_{anomaly}) = \sum_{L2} P(L3_{violation} | L2_{violation}) \cdot P(L2_{violation} | L1_{anomaly})$$

이 전파 확률을 테스트 우선순위 점수로 활용하여, 안전 영향이 큰 하위 계층 이상에 테스트 자원을 집중 배분한다.

#### 3.4.4 계산 복잡도 관리

인과 그래프 학습의 계산 복잡도가 대규모 시스템에서 병목이 될 수 있으므로, 다음 완화 전략을 적용한다:

- **상태 수 상한선**: k ≤ 50 사전 고정
- **점진적 학습**: 새로운 오류 관측이 누적될 때 그래프를 점진적으로 갱신
- **희소성 제약**: L1 정규화로 희소 인과 구조 유도

### 3.5 4단계: FNRA 메트릭 및 Ground Truth 확보

#### 3.5.1 FNRA 메트릭 정의

$$FNRA = \frac{|\text{실제 안전 임계 버그} \cap \text{탐지 실패}|}{|\text{실제 안전 임계 버그}|}$$

FNRA가 낮을수록 더 많은 안전 임계 버그를 탐지하는 우수한 테스팅 시스템임을 의미한다.

#### 3.5.2 삼중 Ground Truth 검증 체계

**(i) 전문가 레이블링:**
- 도메인 전문가 3인이 독립적으로 각 버그의 안전 임계성 레이블링
- Cohen's κ ≥ 0.8 합의 기준 적용
- 불일치 케이스는 중재자(4번째 전문가) 판정

**(ii) CVE/버그 리포트 데이터베이스 매핑:**
- NIST NVD, MITRE CVE 데이터베이스에서 관련 취약점 추출
- 자율주행 도메인: AUTOSAR, ISO 26262 관련 버그 리포트
- 산업 결함 검출 도메인: IEC 61508 관련 사례

**(iii) 변이 테스팅(Mutation Testing):**
- 표준 변이 연산자(경계값 변경, 논리 연산자 교체, 조건 부정) 적용
- 생존 변이체(survived mutants)를 미탐지 버그의 대리 지표로 활용
- 변이 점수(mutation score) ≥ 0.85 목표

세 방식의 ground truth 일치율을 Fleiss' κ로 측정하여 메트릭 신뢰성을 보고한다.

### 3.6 실험 설계

#### 3.6.1 비교 조건 및 사전 등록

4개 주요 조건과 2개 외부 베이스라인을 사전 등록(pre-registration)하여 비교한다:

| 조건 | 설명 |
|------|------|
| (a) MBTG | 순수 모델 기반 기능 테스팅 |
| (b) ADV | 순수 PGD 기반 적대적 테스팅 |
| (c) SEQ | 순차적 결합 (기능→적대적 순서) |
| **(d) HATO** | **제안 시스템 (교차 강화 + 인과 그래프)** |
| (e) DeepXplore | 외부 베이스라인 |
| (f) RobOT | 외부 베이스라인 |

#### 3.6.2 통계 검정 계획

- **주요 검정**: McNemar 검정 (버그 탐지 여부 이진 비교)

def load_data(filepath=None):

        else:
            raise ValueError(f"지원하지 않는 파일 형식입니다: {ext}")

    print(f"[INFO] 데이터 로드 완료: {df.shape[0]}행 x {df.shape[1]}열")
    return df


def preprocess_data(df):
    """
    데이터 전처리 함수
    - 결측치 처리
    - 이상치 탐지 및 처리
    - 특성 스케일링
    """
    print("\n[전처리] 시작...")

    # 결측치 확인
    missing = df.isnull().sum()
    if missing.any():
        print(f"[전처리] 결측치 발견:\n{missing[missing > 0]}")
        # 수치형: 평균으로 대체 / 범주형: 최빈값으로 대체
        for col in df.columns:
            if df[col].dtype in [np.float64, np.int64]:
                df[col].fillna(df[col].mean(), inplace=True)
            else:
                df[col].fillna(df[col].mode()[0], inplace=True)
        print("[전처리] 결측치 처리 완료")
    else:
        print("[전처리] 결측치 없음")

    # 수치형 컬럼 선택
    numeric_cols = df.select_dtypes(include=[np.number]).columns.tolist()

    # 이상치 탐지 (IQR 방법)
    outlier_info = {}
    for col in numeric_cols:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - 1.5 * IQR
        upper = Q3 + 1.5 * IQR
        outliers = df[(df[col] < lower) | (df[col] > upper)]
        if len(outliers) > 0:
            outlier_info[col] = len(outliers)

    if outlier_info:
        print(f"[전처리] 이상치 탐지: {outlier_info}")
    else:
        print("[전처리] 이상치 없음")

    # 특성 스케일링 (수치형 컬럼)
    scaler = StandardScaler()
    df_scaled = df.copy()
    if numeric_cols:
        df_scaled[numeric_cols] = scaler.fit_transform(df[numeric_cols])

    print("[전처리] 완료\n")
    return df, df_scaled, scaler, numeric_cols

def group_analysis(df, group_col='group', target_col='target'):
    """
    그룹별 비교 분석
    - 그룹 간 평균 비교
    - 일원분산분석 (One-way ANOVA)
    """
    print("\n" + "=" * 50)
    print(f"[분석] 그룹별 분석: {group_col} → {target_col}")
    print("=" * 50)

    if group_col not in df.columns or target_col not in df.columns:
        print("[경고] 지정한 컬럼이 존재하지 않습니다.")
        return None

    # 그룹별 기술 통계
    group_stats = df.groupby(group_col)[target_col].agg(
        ['mean', 'std', 'count', 'median']
    ).round(3)
    print(group_stats)

    # ANOVA 검정
    groups = [group[target_col].values for _, group in df.groupby(group_col)]
    if len(groups) >= 2:
        f_stat, p_value = stats.f_oneway(*groups)
        print(f"\n[ANOVA] F-통계량: {f_stat:.4f}, p-값: {p_value:.4f}")
        if p_value < 0.05:
            print("[결과] 그룹 간 유의미한 차이가 있습니다 (p < 0.05)")
        else:
            print("[결과] 그룹 간 유의미한 차이가 없습니다 (p >= 0.05)")

    return group_stats

def pca_analysis(df_scaled, numeric_cols, n_components=2):
    """
    주성분 분석 (PCA)
    - 차원 축소 및 분산 설명력 확인
    """
    print("\n" + "=" * 50)
    print("[분석] 주성분 분석 (PCA)")
    print("=" * 50)

    if len(numeric_cols) < 2:
        print("[경고] PCA를 위해 수치형 컬럼이 2개 이상 필요합니다.")
        return None, None

    n_components = min(n_components, len(numeric_cols))
    pca = PCA(n_components=n_components)
    pca_result = pca.fit_transform(df_scaled[numeric_cols])

    explained_var = pca.explained_variance_ratio_
    for i, var in enumerate(explained_var):
        print(f"  PC{i+1} 분산 설명력: {var:.4f} ({var*100:.2f}%)")
    print(f"  누적 분산 설명력: {explained_var.sum():.4f} ({explained_var.sum()*100:.2f}%)")

    return pca, pca_result
